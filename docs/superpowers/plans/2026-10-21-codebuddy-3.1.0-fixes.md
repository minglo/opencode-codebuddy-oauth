# CodeBuddy 插件缺陷修复（3.1.0）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复模型发现缓存、刷新触发、11133 重试超时与请求快照四个环节的 7 条已证实缺陷，发布 3.1.0，并让 README 与实现一致。

**Architecture:** 三处语义修正 + 一处生命周期修正。模型发现引入「成功目录 / 暂时失败」二分，并把缓存与 in-flight 按连接身份隔离；刷新比较改为完整定义指纹；11133 重试把「等待预算」与「响应体生命周期」拆开；请求快照随响应结束释放。

**Tech Stack:** TypeScript ESM、Vitest 4、OpenCode V2 插件 API（`@opencode/plugin`）、tsup。

**Spec:** 本会话对话结论（无独立设计文档）。已证实的缺陷清单与证据见下方 Global Constraints；每条都附带可复现测试或宿主源码依据。

## Global Constraints

- 目标版本 `3.1.0`，`package.json` 的 `version` 与 README 版本说明同步。
- 不修改 `@opencode/*` 依赖，不新增运行时依赖。
- 不改变已有公开行为：`CODEBUDDY_SSE*`、`CODEBUDDY_CONVERSATION_MAP_MAX`、X-Conversation-ID 稳定化、variants 直通、`DEFAULT_MODEL` 字段值（`{id:"auto",name:"Auto",maxInputTokens:168000,maxOutputTokens:32000,supportsToolCall:true}`）全部保持原样。
- 缓存键与任何日志、持久化中**不得出现原始 token**；只用连接身份（`credential:<id>` / `env:<name>`）。
- `DiscoveryResult` 契约：`{ ok: true; models: RemoteModel[] } | { ok: false; status?: number }`。`fetchRemoteModels` 与 `DiscoveryCache` 的 `fetchFn` 均返回它；所有测试 mock 必须遵守，禁止返回裸数组。
- 所有 mock 测试里对 `AbortSignal.timeout` 的断言必须用导入的 `RETRY_TIMEOUT_MS`（45000），不得写字面量 `30000`。
- 修完 `npm test` 与 `npm run build` 必须全绿；现有 125 项用例不允许被删除（可被修正断言，但需在 commit message 里说明）。

### 已撤回（不在范围，勿重复引入）

- **N1（content-length 不匹配导致重发挂死）**：宿主 `FetchHttpClient.js:51-53` 在调用 `fetch` 前无条件移除 `content-length`，由 undici 按实际 body 重算。不存在该问题。
- **N2（用户配置 provider 时模型列表冻结）**：`core/src/model.ts:133-150` 的 `model.transform` 能向已存在 provider 新增模型，`applyModels` 已覆盖该路径。
- **A（TTL 定时器与缓存 TTL 同值导致不刷新）**：实测定时器触发时 `now - fetchedAt` 恰为 `TTL - 首次fetch耗时 < TTL`。
- **I（fetchJson 超时不覆盖 body）**：abort 能中断 body 读取。
- **L（下架模型滞留）**：provider/model state 每次 fold 从空表重建，删除是隐式的。

## Review Focus

1. 发现请求失败但**已有**同账号有效目录时，用户应当继续看到上次的模型，而不是 `auto` 或空表。
2. 用户在 TTL 内切换账号 A→B，B 应当看到 B 的目录；A 的 in-flight 请求晚到不得污染 B。
3. 11133 重试成功返回的长回答应当能完整流式读完，不被 30 秒预算截断。
4. 同一账号 token 轮换（refresh 后 access 变化）不应触发重新发现。
5. 非 11133 的正常请求结束后，内存中不应继续保留其完整 body 与 `Authorization`。

`src/provider.ts` 的 `load`：

```ts
const resolved = await resolveConnectionIdentity(ctx, state);
if (!resolved) { state.discovered = [DEFAULT_MODEL]; return; }
if (resolved.credential.type !== "oauth" || !resolved.credential.access) { state.discovered = [DEFAULT_MODEL]; return; }
try {
  state.discovered = await state.discoveryCache.get(resolved.accountKey, resolved.credential.access, { signal: undefined });
} catch (e: any) {
  if (e?.status === 401 || e?.status === 403) {
    state.logger.warn("discovery 401/403 — 需重新登录（/connect codebuddy）");
  } else {
    state.logger.warn(`discovery failed: ${e?.message}`);
  }
  state.discovered = state.discovered?.length ? state.discovered : [DEFAULT_MODEL];
}
```

`credential.switched` 分支在 `refresh()` 之前调用 `state.discoveryCache.invalidate(accountKey)`（`accountKey` 用**旧**连接身份；实现上在 `refresh` 开头先算一次再比对，或在事件里传 `data.credentialID` 直接构造 `credential:<id>`）。

`src/index.ts` 的 `fetchFn` 改为消费 `DiscoveryResult`：`ok` 为真返回 `models`，否则 `throw new DiscoveryTransientError()`。
